# known issues

Metainfo: write issues as checkable markdown list items here for future reference. Update upn tackling the issue to keep list fresh. 

- [x] `packages/voxhub-client/src/voxhub_client/cli.py` is a stale verbatim copy of `packages/voxhub-core/src/voxhub_core/server/cli.py` (same `"""SSH-invoked server CLI."""` docstring, same handlers, imports from `voxhub_core.server.*`). Violates the core/client independence rule in `CLAUDE.md` — client must not depend on core. Needs to be replaced with an actual client-side CLI that drives `SshRunner` against a remote `voxhub-server`. **Resolved:** the client CLI is now a real pull implementation (docstring `"""Annotator-facing CLI for voxhub remote annotation workflows."""`, imports only from `voxhub_client.*` + `voxhub_schema`, drives `SshRunner`/`RsyncTransfer` via `_run_pull`). Core independence is respected.
- [x] Client `push` command is missing — `voxhub_client/cli.py` implements `set-server`, `set-identity`, `whoami`, `list-stores`, and `pull`, but has no `push` subcommand or `_run_push` handler, so annotations cannot be sent back to the server from the client. Tracked as Phase 4 of `docs/plans/launch-readiness-implementation-plan.md`. **Resolved (Phase 4, plan/phase4-push):** `voxhub push <session-dir> [--ontology NAME ... | --unconstrained] [--validate-only] [--force]` ships with the full flow — session trust-chain verification (sidecar → manifest → raw checksum), pre-flight validation via `voxhub_schema.validation` (errors always abort, no flag bypasses; warnings proceed, `--force` only stamps provenance), `prepare-push` (rpc, protocol v3) → rsync upload (`--no-links`, staging addressed by basename per the rrsync contract) → `integrate-annotations` with path-keyed `ChecksumEntry` objects → `cleanup` (non-fatal) → local manifest status flip. The wrapper's rrsync branch is now read-write; symlink defense lives in the client (`--no-links`) and authoritatively in `_run_integrate_annotations` (`invalid_staging_content`). Covered by `test_push.py`, `test_push_e2e.py`, and the extended `test_e2e_sshd.py` (pull → annotate → push over real sshd + rsync + forced command).
- [ ] The SSH forced-command wrapper rejects every client RPC. The client sends `SSH_ORIGINAL_COMMAND="voxhub-server <subcmd> ..."`, but `scripts/deploy/voxhub-forced-command.sh` matches the first whitespace token (`voxhub-server`) against bare subcommand names, so every RPC returns `{"code":"forbidden"}`. Launch-blocking. See task 1.1 of `docs/plans/launch-readiness-implementation-plan.md`.
- [ ] Delete the deprecated per-method server subcommands one release after protocol v2 ships. `voxhub-server list-stores` / `prepare-pull` / `integrate-annotations` / `cleanup` / `healthcheck` are compatibility shims over the `rpc` dispatch (`_shim_*` in `packages/voxhub-core/src/voxhub_core/server/cli.py`), kept for one release for operator muscle memory and rollout overlap per `docs/plans/c-transport-rpc-implementation-plan.md`. Deleting them also removes `_translate_legacy_checksums` (the legacy `<filename>:sha256:<hex>` `--checksums` boundary translation) and the `malformed_checksum_paths` bookkeeping in `_run_integrate_annotations`, leaving path-keyed `ChecksumEntry` as the only checksum format. Operator commands (`gc`, `catalog`, `validate-attributes`) are unaffected and stay plain subcommands.
